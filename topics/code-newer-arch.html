Newer Architectures

Drop-in code for the modern upgrades: GQA (cheaper KV cache), MoE (more params, same FLOPs), a MLA sketch, sliding-window attention, and the Muon optimizer. Concepts are on Attention Variants and Optimizer Frontier; here is code you can drop into the Llama-style block.

1. Grouped-query attention (GQA)

Fewer K/V heads than Q heads, each shared across a group of query heads — shrinking the KV cache by n_heads / n_kv_heads× at almost no quality cost. The only new piece is repeat_kv, which broadcasts each KV head to its group before the attention matmul.

2. Mixture of Experts (MoE)

        

          Replace the single MLP with E experts and a router that sends each token to its
          top-k. Total params scale with E; per-token FLOPs scale with
          k. The load-balancing auxiliary loss keeps the router from
          collapsing onto a few experts (Transformer Internals §7).
        

        


        

        

          Real MoE adds capacity factors / dropless routing and spreads experts across devices with
          expert parallelism and an all-to-all (Distributed
          §2). Add aux_loss (times a small coefficient) to the training loss.
        


        
        
3. Multi-head Latent Attention (MLA) — sketch

        

          DeepSeek's trick to shrink the KV cache while keeping softmax attention: project K/V down to a
          small latent c_kv, cache only that, and up-project when
          needed. The cache stores d_latent per token instead of 2·n_heads·head_dim.
        

        


        


        
        
4. Sliding-window attention

        

          Bound the cost of long context: each position attends only to itself and the previous
          window − 1 tokens (Mistral). Just a different mask.
        

        


        


        
        
5. The Muon optimizer

        

          Momentum orthogonalized by Newton–Schulz — for 2D weight matrices only (embeddings, the head,
          and norms stay on AdamW). See Optimizer Frontier §4 for
          the why; here is a compact implementation.
        

        


        

        

          
⚠️ Muon is 2D-only — route parameters

          

            Give Muon only the weight matrices; put embeddings, the LM head, and norm/bias params in a
            separate AdamW optimizer. A "Muon run" is always Muon + AdamW
            (Optimizer Frontier §4).

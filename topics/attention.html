Attention: Scratch → Efficient

Attention is the heart of the transformer, and implementing it from scratch is the single best exercise for understanding LLMs. This page walks from the raw math to a from-scratch implementation, then to the efficiency story — GQA, KV cache, FlashAttention — that turns the textbook version into the one production systems actually run.

1. Scaled dot-product attention, from the definition

Attention lets each position build a query, compare it against every position's key, and read out a weighted mix of values. With queries Q ∈ ℝ^{T×d}, keys K ∈ ℝ^{T×d}, values V ∈ ℝ^{T×d}:

Attention(Q, K, V) = softmax( QKᵀ / √d ) V

QKᵀ is a (T×T) matrix of similarity scores; the row-wise softmax turns each query's scores into a distribution over positions; multiplying by V reads out the weighted average. Three things to be able to justify on demand:

  • Why divide by √d? Q and K entries are ~unit variance, so each dot product over d terms has variance ~d. Without the 1/√d scale, logits grow with d, pushing softmax into saturated regions where gradients vanish. The scale keeps logit variance ~1.
  • Softmax is row-wise — over the keys axis. Getting the axis wrong is the most common bug; each query must sum to 1 over keys.
  • Shapes: scores (T,T), output (T,d) — same shape as the input, which is what lets you stack blocks.

2. Causal masking

        

          A decoder LM must not let position t attend to future positions. We enforce
          this by setting the scores above the diagonal to −∞ before the
          softmax, so their weights become exactly 0. Use −∞ (or a large negative like
          −1e9), never a post-softmax zero-out — masking after softmax breaks the
          normalization.

⚠️ Gotcha: −inf rows and NaNs

          

            If an entire softmax row is −inf (can happen with padding masks on empty
            positions), exp gives all zeros and you divide 0/0 → NaN. The
            causal mask never fully masks a row (position t always sees itself), but
            padding masks can. Real kernels guard this; worth mentioning if asked about edge cases.
          

        


        
        
3. Multi-head attention

        

          One attention head can only average one way. Multi-head attention runs H
          attention operations in parallel on d = D/H-dimensional projections, letting
          different heads specialize (syntax, coreference, positional patterns). The heads are
          concatenated and mixed by an output projection W_o.
        

        

          The implementation trick is to do it with batched matmuls, not a Python loop over
          heads: project to d_model, reshape to (batch, seqlen, n_heads, head_dim),
          transpose to (batch, n_heads, seqlen, head_dim), and let the last two axes be the matrix dims. (Revisit the
          reshape/transpose mechanics on Python & Tensor Fluency.)

4. MHA → MQA → GQA

        

          At inference, the KV cache (next section) dominates memory. Multi-Query Attention (MQA)
          shares a single K/V head across all query heads; Grouped-Query Attention (GQA)
          interpolates — G KV heads shared by groups of query heads. GQA is the modern
          default (Llama-2 70B, Llama-3, most current models) because it cuts KV-cache size by
          H/G× with almost no quality loss.
        

        

          

            
SchemeQuery headsKV headsKV cache vs MHATrade-off

            
              
MHAHH1×Best quality, largest cache

              
GQAHG (1<G<H)G/H×Sweet spot; near-MHA quality

              
MQAH11/H×Smallest cache, some quality loss

            
          

        

        

          Implementation-wise, GQA just means K and V have shape (B, G, T, d) and you
          repeat each KV head to serve H/G query heads before the score
          matmul (torch.repeat_interleave along the head axis, or broadcast).
        


        
        
5. The KV cache

        

          Autoregressive generation produces one token at a time. Naively, generating token
          t re-runs attention over all t positions — O(T²)
          recompute for a sequence. The KV cache stores the K and V projections of all past tokens,
          so each new step computes attention with a single new query against the cached keys/values:
          per-step cost drops from O(t·d) recompute of K/V to O(d). This is
          the difference between usable and unusable inference. (Raschka's Build a Reasoning
          Model §2.8 walks a minimal implementation if you want a reference.)
        

        

          
KV cache memory — know this formula cold

          

            bytes = 2 (K & V) × layers × seqlen × kv_heads × head_dim × bytes/elt × batch

6. FlashAttention — the efficiency centerpiece

        

          Standard attention materializes the full (seqlen × seqlen) scores matrix in HBM
          (GPU main memory). That matrix is O(seqlen²) in memory and, crucially, attention
          is memory-bandwidth bound: the arithmetic is cheap relative to the HBM reads
          and writes of that big intermediate. FlashAttention (Dao et al., 2022) computes exact
          attention without ever writing the full scores matrix to HBM, by tiling the
          computation and keeping tiles in fast on-chip SRAM.
        

        
The two ideas:

        
    
          
  • Tiling: process blocks of queries against blocks of keys/values, keeping
            the working set in SRAM. HBM traffic drops from O(seqlen²) to
            O(seqlen²/M) where M is the SRAM size — a large constant-factor win.
    • 
          
  • Online softmax: to combine block results without seeing all keys at once,
            maintain a running max and running normalizer, rescaling the accumulated output as each new
            block arrives. This makes the result exact, not an approximation — a point
            is often misunderstood.
    • 
        

        

          You rarely need to write CUDA yourself, but you should be able to explain online softmax. In
          PyTorch you don't implement it yourself — F.scaled_dot_product_attention
          dispatches to a FlashAttention kernel. The cell confirms SDPA returns exactly the plain,
          fully-materialized result.
        


        

          

            SDPA (FlashAttention) == the plain computation
            
            
            
          

          
          

        


        

          
Why this matters

          

            If asked "why is FlashAttention faster if it does the same FLOPs (or slightly more)?",
            the answer is the roofline: attention is memory-bound, so cutting HBM traffic — not
            FLOPs — is what buys speed. FlashAttention trades a bit of recompute for far less memory
            movement, and also drops peak memory from O(T²) to O(T), which
            is what unlocks long context. FlashAttention-2/3 refine the work partitioning and use
            newer-GPU features; know they exist.
          

        


        
        
7. Roofline & arithmetic intensity

        

          The mental model behind every "is this kernel good?" question. Arithmetic intensity =
          FLOPs / bytes moved. A kernel is compute-bound if its intensity exceeds
          the hardware's FLOP:bandwidth ratio (the "ridge point"), else
          memory-bound. Big dense matmuls (like the FFN) are compute-bound; softmax,
          layernorm, elementwise ops, and naive attention are memory-bound. This is why
          kernel fusion and FlashAttention matter: they raise arithmetic intensity by avoiding
          round-trips to HBM.
        

        

          A100: ~312 TFLOP/s (bf16) ÷ ~2.0 TB/s HBM ≈ 156 FLOP/byte ridge point. 

          Below that intensity → you're bandwidth-limited.

            Count attention FLOPs and find the bottleneck
            
          

          

            For a single attention layer with batch B, seq T, model dim
            D: write expressions for the FLOPs of (a) the QKV projections, (b) the
            QKᵀ scores, (c) the ×V readout, (d) the output projection. At
            what sequence length T does the O(T²) attention term overtake
            the O(T·D²) projection term? (This is why long context is expensive and why
            attention-efficiency is a whole research area.)
          

          

            Show answer sketch
            

              Projections: ~3·2·B·T·D² (QKV) + 2·B·T·D² (out).
              Scores + readout: ~2·2·B·T²·D. The attention term overtakes the
              projection term when T ≳ D (roughly). So for D≈4096,
              attention cost dominates once context passes a few thousand tokens — the regime where
              FlashAttention and linear/sparse-attention variants earn their keep.

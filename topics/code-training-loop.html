The Training Loop

Everything around the model: batching, the AdamW parameter groups, warmup+cosine LR, gradient accumulation, mixed-precision autocast, gradient clipping, checkpointing, and generation. The concepts live on Training Dynamics and Numerics; this is the code that ties them together.

1. Batching

Data is one long 1-D tensor of token ids. Sample random windows; the target is the input shifted by one (next-token prediction).

2. Optimizer with weight-decay groups

A detail that matters: decay the 2D matrices (Linears, embeddings) but not the 1D params (norm gains, biases). Two param groups, one AdamW. Use fused=True on CUDA for a faster step.

3. Learning-rate schedule

Linear warmup, then cosine decay to a floor. The reference schedule from every LLM recipe.

See the schedule (PyTorch) 

        


        
        
4. Evaluation

        
Average loss over a few batches, under no_grad and eval mode.

        


        


        
        
5. The loop

        

          The whole thing: set the step's LR, accumulate gradients over several micro-batches under
          bf16 autocast, clip the global gradient norm, step, and periodically eval +
          checkpoint. bf16 needs no GradScaler (its range is wide enough — see
          Numerics); fp16 would.
        

        


        

        

          
⚠️ A resumable checkpoint needs more than weights

          

            To resume exactly, the checkpoint must also carry the optimizer state (Adam's
            moments), the step count (so the LR schedule continues), and ideally the RNG + dataloader
            position. Saving only model.state_dict() restarts momentum and the schedule —
            see Infra & Tooling §2.
          

        


        
        
6. Generation

        

          Autoregressive sampling with temperature and top-k. Note it re-runs the whole context each
          step — correct but O(T²); production caches K/V (see
          Attention §5).
        

        


        


        

          
Reading checklist

          

            You can explain: why weight-decay is split by param dimensionality; why zero_grad
            is once per accumulation window and the loss is divided by grad_accum; why bf16
            autocast needs no scaler; what global-norm clipping does; and what a checkpoint must contain
            to resume. Each links to a concept page if it's fuzzy.
          

        


        

          

            Local exercise
            Prove your checkpoint resumes correctly
            
          

          

            Train 100 steps, checkpoint, and continue to 200. Separately, train straight through to 200
            with the same seed. Confirm the loss curves match after resume (within seed noise). Then
            deliberately drop the optimizer state from the checkpoint and watch the loss bump at resume —
            the momentum-reset failure mode made visible.

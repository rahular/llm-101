Synthetic Data

High-quality human text is running out, and synthetic data is now central to frontier training — for capability injection, alignment, and reasoning. This page covers the generation techniques (distillation, instruction synthesis, rejection sampling, self- improvement) and the failure mode that governs all of them: model collapse.

Prerequisite

Pairs with Data & Tokenization (the pipeline for real data) and RL for Post-training (which consumes much of this data). The unifying tension: synthetic data lets you generate unlimited targeted examples, but a generated distribution is only as good as the generator and the filter — quality control is the technique.

1. Why synthetic data

  • The data wall. The stock of high-quality human text is finite and largely already used; scaling laws want more tokens than exist. Synthetic data extends the supply.
  • Targeted capability. You can generate exactly the distribution you're weak on — math, code, tool use, a low-resource language, a reasoning format — instead of hoping the web contains it.
  • Cost & control. Generation + automated filtering is far cheaper than human labeling, and you control difficulty, style, and coverage.
  • Verifiability. In domains with a checker (math answers, code tests), you can generate and validate at scale — the highest-quality synthetic data there is.

2. Distillation — the workhorse

The single most impactful technique: use a strong teacher model to generate data for a smaller/cheaper student. This ranges from hard-label distillation (train on the teacher's generated text) to on-policy distillation (student generates, teacher scores/corrects) and sequence-level KD (match the teacher's output distribution). Most open "instruct" models are, in part, distilled from a stronger model. The caveat is legal/ToS and the fact that a student generally can't exceed its teacher on the distilled distribution.

3. Instruction & prompt synthesis

Bootstrapping instruction-tuning data from a model itself:

  • Self-Instruct / Alpaca — seed with a few human instructions, have the model generate many more (instruction, input, output) triples, filter, and fine-tune on them.
  • Evol-Instruct (WizardLM) — evolve prompts to be harder and broader: in-depth evolving (add constraints, deepen reasoning) and in-breadth evolving (new topics).
  • Persona-driven (Persona-Hub) — condition generation on a huge set of personas to get diversity at scale, mitigating the mode-collapse of "the model always writes the same kind of example."
  • CoT-Self-Instruct (2025) — the model reasons/plans via chain-of-thought about a seed task before generating new examples, then a quality filter selects the best — higher-quality prompts for both reasoning and non-reasoning tasks.

4. Rejection sampling & STaR (verifiable domains)

Where you can check an answer, generation quality skyrockets. Rejection sampling (a.k.a. best-of-N + filter, or rejection-sampling fine-tuning / RFT): sample many candidate solutions per problem, keep only the ones that pass the checker, and train on those. STaR (Self-Taught Reasoner) closes the loop: generate rationales, keep those that reach the correct answer, fine-tune, repeat — the model bootstraps its own reasoning traces. This is a backbone of modern reasoning-model data pipelines.

5. Rephrasing & augmenting real data

        

          Rather than generate from scratch, transform existing data:
        

        
    
          
  • WRAP (rephrasing the web) — rewrite noisy web text into clean styles
            (Wikipedia-like, Q&A), improving quality and giving multiple views of the same content;
            trains faster to a given loss.
    • 
          
  • "Textbook-quality" (Phi series) — generate/curate textbook- and
            exercise-like data; the thesis that small models trained on very high-quality (often
            synthetic) data punch far above their size.
    • 
          
  • Back-translation & format conversion — turn documents into instructions,
            code into explanations, etc., to manufacture task-shaped data from raw corpora.
    • 
        


        
        
6. Self-improvement loops

        
    
          
  • RLAIF / Constitutional AI — use an AI to provide the preference/critique
            signal (against a written "constitution") instead of humans, then train on it. Scales
            alignment feedback. (See RL for Post-training.)
    • 
          
  • Self-rewarding / self-play — the model generates, judges, and improves on
            its own outputs across rounds. Powerful, but the tightest possible loop and thus the most
            exposed to the collapse risk below.
    • 
        


        
        
7. The governing failure mode: model collapse

        

          Train a model on its own (or another model's) outputs repeatedly, and the distribution
          narrows — tails vanish, diversity drops, and errors compound generation over
          generation. This model collapse is the central risk of synthetic data. The
          intuition: sampling-then-refitting loses the rare events each round, so variance shrinks toward
          the mean. The cell demonstrates it with a Gaussian refit loop.

The defenses, which double as the quality-control toolkit:

        
    
          
  • Anchor with real data — always mix a meaningful fraction of human data;
            never train purely on model output round after round.
    • 
          
  • Filter on three axes — complexity, quality, and diversity (the standard
            framing). For non-verifiable data, methods like RIP score instructions by the reward-model
            distribution of their sampled responses.
    • 
          
  • Verify where possible — checker/execution feedback beats any learned filter.
    • 
          
  • Measure diversity — track n-gram/embedding diversity and distribution
            coverage, not just average quality, so you catch narrowing early.
    • 
          
  • Decontaminate — synthetic data can leak eval content just like scraped data
            (see Data & Tokenization).
    • 
        


        

          
Why this matters

          

            The mature take: synthetic data is not "free tokens" — it's a generator + filter
            pipeline whose value is bounded by both. Strong answers name the domain split
            (verifiable math/code, where rejection sampling is gold, vs non-verifiable
            open text, where you rely on reward-model/LLM-judge filtering and diversity control), cite
            model collapse as the reason you always anchor with real data, and treat "does this synthetic
            set actually help?" as an ablation question (see
            Scaling Laws), not a foregone conclusion.

            Local exercise
            Break and fix model collapse
            
          

          

            Extend the collapse cell to a richer distribution (a mixture of Gaussians, or a small
            char-level LM). Run the self-refit loop and quantify diversity loss (e.g. entropy, unique
            n-grams, mode coverage) per generation. Then show that mixing in a fixed fraction of real
            samples each round stabilizes the distribution. This is the empirical core of every
            "will synthetic data hurt us?" discussion.
